# API Design 16: Documents, Media Library, Uploads, Imports, Exports, Generated PDFs, and Storage Retention

Project: Restaurant POS ERP  
Backend: Laravel, PHP 8.3, PostgreSQL, database-per-tenant multitenancy  
API version: v1  
Date: 2026-08-25

## 1. Purpose

This design covers:

```text
file uploads
menu images
company/branch logos
supplier/customer/staff documents
purchase/tax/payroll attachments
generated PDFs
Excel/CSV imports
report exports
storage and retention
```

Files must be stored in filesystem/object storage, not inside PostgreSQL.

Database stores metadata, ownership, review status, import results and links.

## 5. Tenant storage path strategy

Every file path must include tenant UUID.

Recommended pattern:

```text
tenants/{tenant_uuid}/{collection}/{year}/{month}/{file_uuid}.{ext}
```

Examples:

```text
tenants/tenant-uuid/menu_item_images/2026/08/file.jpg
tenants/tenant-uuid/company_logo/2026/08/logo.png
tenants/tenant-uuid/report_exports/2026/08/report.pdf
```

This avoids mixing tenant files.

## 7. Document versions

`business_document_versions` stores file version metadata.

Example:

```text
Version 1: original supplier invoice
Version 2: corrected invoice
```

Only one active current version is allowed.

Use checksum:

```text
checksum_sha256
```

to help detect duplicate/re-uploaded files.

## 10. Imports

`data_import_batches` stores import job summary.

Supported first-release import areas:

```text
menu
ingredients
suppliers
customers
staff
stock_opening
prices
chart_accounts
```

`data_import_errors` stores row-level validation errors.

Import flow:

```text
Upload Excel/CSV
Create business_document
Attach file to media collection import_files
Create data_import_batch
Queue import job
Worker validates rows in chunks
Insert/update valid rows
Store row errors
Mark completed/completed_with_errors/failed
Notify user
```

Do not process large Excel files inside HTTP request.

## 11. Exports and generated PDFs

Exports are generated by queued jobs when large.

Examples:

```text
sales report PDF
stock balance XLSX
payslip PDF
purchase order PDF
receipt PDF
tax return PDF
```

Flow:

```text
Create report_run or business_document
Queue export job
Generate file
Attach file to media
Update report_run/document status
Notify recipient
```

## 12. Upload validation

Validate:

```text
file size
mime type
extension
collection allowed for model
tenant access
branch access
permission
virus/malware scanning when available
image dimensions for logos/menu images
```

Examples:

```text
logo: png/jpg/webp, max 2MB
menu image: png/jpg/webp, max 5MB
document PDF: pdf/png/jpg, max 10MB
import: xlsx/csv, max configured size
```

## 13. Image conversions

For menu and logos, use conversions:

```text
thumbnail
medium
web
```

Generate conversions in queue where possible.

Do not block POS/API request waiting for expensive image processing.

High:

Queue required:

- virus scan if available
- retention cleanup

## 16. Performance and storage rules

Do:

```text
store metadata in DB
store files on disk/object storage
use queues for heavy work
chunk imports
paginate import errors
expire generated exports
archive old documents if required
```

Do not:

```text
store file binary in PostgreSQL
load huge import files into memory
keep temporary exports forever
process big Excel in HTTP request
duplicate documents across modules
```

## 17. Retention

Recommended:

```text
temporary imports: delete/archive after configured period
failed import row payloads: keep short/medium period
generated exports: expire 30-180 days
legal/tax/payroll documents: keep according to policy/law
menu images/logos: keep while referenced
old versions: archive, do not show by default
```

## 18. Access control
